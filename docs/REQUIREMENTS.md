# AI 热点雷达（HotPulse）— 需求文档

> 版本：v1.0 ｜ 日期：2026-09-27 ｜ 状态：待确认

## 1. 背景与目标

作为 AI 应用方向的学习者，需要**第一时间**获取 AI 领域热点（如大模型发布/更新），
不依赖人工手动搜索，而是由工具**自动发现指定热点变化 / 最新热点**，并及时发送通知。

项目定位：轻量工具类项目，敏捷开发，不过度工程化。

## 2. 功能需求

### F1 关键词盯梢（Watch）
- 用户手动输入要监控的关键词（如 `GPT-6`、`Claude Fable`）。
- 系统定期从**多个可信信息源**抓取该关键词的最新内容。
- **AI 甄别假冒内容**（关键要求）：
  - 判定内容与关键词是否**实质相关**（过滤标题党、蹭词、营销软文）；
  - 判定是否为**真实发布/更新**（有无官方来源或可信讨论佐证）；
  - 甄别理由需持久化并在页面展示（可解释）。
- 确认命中后，**第一时间**发送通知。

### F2 范围热点（Radar）
- 用户设定关注范围（如 `AI 编程`、`多模态`、`开源大模型`）。
- **每 30 分钟**自动搜集范围内的热点（多信息源聚合）。
- AI 对原始条目做**聚类去重、热度评分、中文摘要点评**。
- 用户在 Web 页面浏览热点榜/时间线，重要热点同步通知。

### F3 通知
- **站内通知中心**：铃铛 + 未读红点 + 列表，SSE 实时到达。
- **浏览器实时推送（Web Push）**：Service Worker + VAPID，浏览器关闭也能收到系统通知。
- **邮件通知**：SMTP（QQ/163 授权码等），命中即发（可开关）。
- 外部推送均为可选项，未配置时不影响核心功能。

### F4 Agent Skills 封装（第二阶段）
- 封装为 `SKILL.md` + CLI 脚本，交给其他 AI（Copilot / Claude 等）执行
  "添加监控、立即扫描、查热点、查通知" 等操作，复用后端 API。

## 3. 信息源需求（多源，避免单一来源）

| # | 信息源 | 接入方式 | 内容 | 备注 |
|---|--------|----------|------|------|
| S1 | Hacker News | Algolia 公开 API | 技术圈热议 | 免 key |
| S2 | GitHub Trending | 网页爬虫 | 新项目爆发 | 免 key，低频 |
| S3 | HuggingFace Papers / Models | 公开 API/页面 | 论文、新模型发布 | 免 key |
| S4 | 官方博客 RSS | RSS 抓取 | OpenAI / Anthropic / DeepMind / Meta AI / Mistral 等一手官宣 | 免 key |
| S5 | 网页搜索 | DuckDuckGo HTML 端点爬虫 | 通用最新结果 | 免 key，**注意频率**（每次扫描 ≤ 若干查询，带间隔） |
| S6 | Twitter (X) | **twitterapi.io** | 最新推文、KOL 动态 | 需 API key，按次计费 $0.15/1k，免费额度 $0.1 |

- 各源独立失败不影响整体（容错）。
- X 源成本控制：仅对**活跃关键词**与**关注范围**做 `Latest` 搜索，限制每次扫描的调用数。

## 4. AI 能力需求（OpenRouter）

- 通过 OpenRouter（OpenAI 兼容 Chat Completions 接口）调用，模型可配置。
- 用途：
  1. **相关性/真伪甄别**（F1）：输入条目 + 关键词 → 输出 `{relevant, genuine, confidence, reason}`；
  2. **热点聚类与评分**（F2）：输入一批近期条目 + 关注范围 → 输出话题簇 `{title, score, summary_zh, item_ids, why_hot}`；
  3. 输出要求严格 JSON，需解析容错与降级（AI 失败时保留原始数据，不阻塞）。

## 5. 产品形态与非功能需求

- **响应式 Web 页面**：桌面/手机均可舒适使用；设计风格独特（"雷达控制台"暗色风），不用千篇一律的组件库模板。
- **本机运行**为主，结构上保持可移植（后续可部署云服务器）。
- 配置全部走 `.env` / settings 页，密钥不进代码库。
- 数据本地 SQLite 持久化，重启不丢。

## 6. 验收标准

1. 添加关键词后，30 分钟内（或点"立即扫描"后）能抓到多源内容，AI 甄别理由可见，假冒/蹭词内容被过滤的判据可解释。
2. 热点榜每 30 分钟自动更新，同一事件多源条目被 AI 合并为一个话题并给出中文摘要。
3. 命中热点时：站内红点 + 浏览器系统推送 + （配置后）邮件，均能收到。
4. 手机浏览器打开页面布局不错乱。
5. Agent Skill 可被其他 AI 调用完成监控与查询（第二阶段验收）。

## 7. 用户决策记录

- 技术栈：Node.js（Express + SQLite）+ React/Vite。
- 通知：站内 + 邮件 + 浏览器 Web Push（用户补充要求）。
- 运行：先本机，后续再部署。
- OpenRouter key：用户自备（.env 配置）。
- 扫描频率：30 分钟一次。
- 补充：接入网页搜索爬虫（免 API、控频）与 twitterapi.io；多信息源并行；需求与方案先沉淀为 Markdown 文档再开发；技术实现须以 MCP 获取的最新官方文档为准。
