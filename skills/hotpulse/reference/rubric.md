# 甄别与聚类判据（Claude 即 AI 引擎时读这份）

本 Skill 不做任何外部 AI 调用——**判断由执行本 Skill 的你（Claude / Copilot 等）完成**。
这份文档把后端 `server/src/ai/screen.js` 与 `cluster.js` 的提示词判据迁移过来，
保证你给出的结论与 Web 版 HotPulse 一致。`pending` 命令会把工作清单 + 证据字段一起给你。

## 0. 最重要的一条：不要用你的训练知识否定新产品

监控的关键词（如 `GPT-6`、`Claude Fable 5`）很可能是**在你训练截止之后才发布**的产品。
严禁以"该产品在我的知识中不存在"为由判 `genuine=false`。
真伪判定**只看给定来源与佐证**，不看你是否"听说过"。`pending` 输出里会带上当前日期，以它为准。

## 1. 关键词甄别（screen）：判 relevant + genuine

对每个【盯梢关键词 × 条目】组合输出：

```json
{"k":"关键词","i":条目id,"relevant":true,"genuine":true,"confidence":0.9,"reason":"一句话中文理由"}
```

每条都带着**代码预先算好的证据字段**，直接采用，不要自己推测媒体身份：

| 字段 | 含义 |
|---|---|
| `src` | 信息源（blog/news_search/hn/bilibili…） |
| `tier` | 来源分级：1=官方一手 2=强策展社区 3=主流媒体 4=泛搜索/UGC |
| `host` | 真实媒体域名 |
| `eng` | 加权互动分 / 入库门槛 ~ 权威门槛（`0` 表示该源无互动接口，不代表低质） |
| `official=1` | 该域名是厂商官方一手来源 |
| `auth=1` | 在权威媒体名单内 |
| `farm=1` | 内容农场/自媒体转载站（名单判定，无需你识别） |
| `q` | 规则质量分（0-100） |
| `m` | 原始互动徽章（⭐/👍/💬…） |
| `age` | 距今小时数 |

### relevant（是否实质相关）
判 `false` 的情况：仅标题蹭词、营销软文、教程堆砌、排行/横评/导航聚合页、与关键词所指产品/事件/技术本身无关。

### genuine（是否真实可信）——只看来源与佐证
- `official=1` 或 `tier=1` → 一手权威，**true**；
- `auth=1` 的媒体报道 → 属可信转述，**true**。**"没有官方原文"不等于虚假**，多家权威媒体交叉报道本身就是佐证；
- `farm=1`，或 `tier=4` 泛搜索/低热度 UGC 且无 official/auth 来源同题印证 → **false**；
- `eng` 极低的社区随手帖、纯传闻爆料、内容自相矛盾 → **false**。
- ⚠ 不得一边承认"权威媒体报道"一边又以"缺乏官方佐证"判 false——二者矛盾时以 `auth` 字段为准。

### confidence（0~1）
对上述两项结论的把握。低于 `HP_MIN_CONFIDENCE`（默认 0.6）的 relevant+genuine 不会计入命中。

### reason（≤50 字中文）
引用给定证据字段说明依据，如"auth=1 澎湃新闻可信转述""farm=1 自媒体转载蹭词"。**不要复述标题**。

## 2. 热点聚类（cluster）：合并同事件 + 只评量级

把讨论**同一事件/产品**的条目合并为一个话题（跨信息源合并：HN + 官方博客 + 媒体都在说同一个模型发布 → 一个话题）。

```json
{"cluster_key":"gpt6-release","title":"中文标题","summary_zh":"40~90字事实陈述","why_hot":"≤28字新增信息量","score":85,"item_ids":[1,2],"scope":"AI 编程"}
```

### 字段要求
- **cluster_key**：简短稳定英文标识（如 `gpt6-release`）。**同一事件跨轮次必须一致**——`pending` 会列出既有话题的 key，命中就沿用、把新条目并入，别另开。
- **title**：中文 ≤28 字，写"主体 + 动作 + 关键对象"，不堆形容词、结尾不带标点。
- **summary_zh**：40~90 字，只陈述事实（谁、做了什么、关键数字/规格/时间）。禁止复述标题、禁止"引发关注"这类评价。
- **why_hot**：≤28 字，说明**新增信息量**（改变了什么、对谁有实际影响）。禁止空泛套话（"行业关注度极高""备受瞩目"一律不许）。
- **item_ids**：属于该话题的条目 id 数组（**只能引用 `pending` 给定的 id**）。
- **scope**：从 `pending` 列出的关注范围里选最相关的 label，无则空字符串。

### 主体一致性硬规则（防"话题黑洞"）
话题内每条标题/摘要都必须明确提及**同一主体**（同一产品名/公司名/事件对象）。以下**禁止**并入既有话题：
- 主体不同："GPT-6 宕机赔偿" ≠ "DeepSeek 宕机赔偿"，即使事件类型相同；
- 顺带提及："AI 圈诸神之战"盘点里一句带过 GPT-6，主体其实是别的事；
- 二创/娱乐内容：用模型生成的歌曲/游戏视频/手书，消费的是模型名而不是模型事件本身。

> commit 会用 `subjectTokens` 对每个话题做主体硬校验，标题提不出拉丁词（纯中文话题）则跳过校验（宁放过不误杀）。

### score（0~100）——只评事件量级
**不要考虑传播热度**：热度由代码按互动数据另算并合成（`score = 0.6×你的基线 + 0.4×互动分量`，再按证据等级封顶）。判定顺序：
- 全新模型 / 重大能力 / 开源权重 / 行业级合作落地 → **85~100**；
- 现有产品的常规版本迭代、小功能更新、客户案例软文、活动预告、综述/榜单类 → **60~75**，即使 `official=1` 也不给 85 以上；
- 旧闻转述、纯观点评论 → **≤60**。
- ⚠ GitHub 老仓库（tensorflow/vscode 级）常驻 trending 榜，"总星数高"不是热点，只有 `stars_today`（当日新增）才是信号。
- 条目里的 `eng`/`m` 互动数据**不必**用来调分——代码会把话题互动总量按权重并入。

### 封顶与证据等级（代码自动算，你无法自我抬分）
| 等级 | 触发条件 | 分数上限 | 可否当热点通知 |
|---|---|---|---|
| 官方一手 official | 含厂商官方一手条目 | 100 | 是 |
| 媒体交叉 media_cross | ≥2 家不同权威媒体域名 | 100 | 是 |
| 多源爆款 viral_social | ≥2 条社交爆款 | 80 | 是 |
| 爆款孤证 single_viral | 仅 1 条社交且够热 | 65 | 否 |
| 弱社交 social_weak | 纯社交不够热 | 60 | 否 |
| 单源弱佐证 weak | 其余（单源孤证） | 65 | 否 |

所以"1 条孤证给 100 分""随手发帖成热点"会被代码拦下——你只管按量级给基线分。

## 3. commit 文件完整结构

```json
{
  "verdicts": [
    {"k":"GPT-6","i":64,"relevant":true,"genuine":false,"confidence":0.4,"reason":"新浪热点榜聚合页转述，无官方佐证，疑似蹭词"}
  ],
  "topics": [
    {"cluster_key":"anthropic-source-control-rewrite","title":"Anthropic 重构源码控制工作流","summary_zh":"…","why_hot":"…","score":78,"item_ids":[54,63],"scope":"AI 编程"}
  ]
}
```
两个数组都可省略其一（只做聚类就不写 verdicts）。写回：`node scripts/hp.mjs commit --file <路径>`。
